# Collaboration release: API contract and rollout

## API contract
All operations reuse authenticated workspace/actor and existing relay scopes. Never trust a supplied workspace or sender identity. Existing job APIs remain compatible. New beta UI is opt-in per workspace.

MCP operations: get_collaboration_config (read), send_message (send), get_conversation (read), list_conversations (read), preview_requests (read), claim_request (work), reply_to_request (work), check_conversation_inbox (read), acknowledge_conversation (read delivery acknowledgement). Existing submit_result/ask_question/answer_question remain usable.

HTTP: GET /v1/configuration; GET/PUT /v1/agents/:id/collaboration; PATCH /v1/agents/:id/onboarding; GET/PUT /v1/workspace/release; GET/POST /v1/conversations; GET /v1/conversations/inbox?consumer_id=...; GET /v1/conversations/:id; POST /v1/conversations/:id/messages; PATCH /v1/conversations/:id/context; GET /v1/requests/pending; POST /v1/requests/:id/claim; POST /v1/requests/:id/reply; POST /v1/conversations/:id/acknowledge; POST /v1/conversations/:id/stop; POST /v1/conversations/:id/extend. Owner activation routes: GET/PUT/DELETE /v1/agents/:id/activation and GET /v1/requests/:id/activation.

Settings shape follows collaboration.ts exports. Conversation request shape follows conversations.ts exports. Idempotency is required in generated agent instructions and reused on retries. Claim IDs use existing fencing. Stable inbox consumer IDs isolate delivery cursors. Claim consumer IDs are fresh per execution and only reused for retries within that execution; neither kind grants authentication or independent provider routing.

Owner configuration includes `settings.instructions: { profile, custom_prompt }`. The primary profiles are `judgment` and `available`; `delegate`, `offload`, `collaborate`, and `second_opinion` remain compatible. New or missing preferences read as `judgment`/`null`; saved selections and custom text are preserved without rewriting policy. Custom text is capped at 16,000 characters, participates in existing aggregate settings/storage caps, and is protected by the configuration version. Profile-only edits preserve custom text and all permissions. Short setup prompts introduce the saved preference. Authenticated `runtime_instructions` supplies current protocol guidance and a readable profile preference; custom text remains in one canonical `settings.instructions.custom_prompt` field. Background tasks refresh this configuration instead of embedding a stale profile. No additional migration is required for this onboarding update.

`readiness.peer_collaboration` adds a stricter milestone alongside the compatible `collaboration` field: a completed and retrieved exchange between two distinct, existing assistant connections in the same workspace. Owner-created marker tests and self-exchanges do not qualify. Onboarding `step: done` atomically requires this proof and authenticated contact; incomplete setup can still be saved. The [user guide](connecting-assistants.md) describes the flow and provider instructions.

The background verification recorder remains an internal, unused hook. A Code API launch acknowledgment and subsequent calls with a shared connector credential do not authenticate the responding session or originating scheduled reader. The application therefore does not wire those events into a false background-verification claim. Trusted execution correlation and the live unattended return path remain release gates.

Owners can pin approved text and links with version-checked saves. Every change preserves the previous and new text in conversation history. Pickup carries the full current context and its version; oversized essential content explicitly requests a smaller brief. Pinned context participates in storage accounting, export, and whole-conversation retention. New strict conversations retain 30 days after their last message; legacy records keep their existing retention policy. Outstanding requests prevent expiry.

## Local preview and rollout

Run `node scripts/preview-next.mjs` for a loopback-only preview of the actual production interface and Worker API using migrated, in-memory synthetic data. It prints a temporary fixture sign-in link. External provider networking is blocked, and closing the process removes the data. `--check` validates the fixture without opening a port.

The static hosted build contains `/app-next`; single-origin/self-host deployments expose `/beta`. Opening either page does not enable anything. The owner explicitly opts in through `PUT /v1/workspace/release`. Existing `/app` users redirect only after their workspace is enabled; `?experience=legacy` keeps the earlier interface available. New MCP tools and HTTP conversation/configuration routes are hidden/blocked until enabled. Hosted workspaces cannot use the self-host environment override.

For an operator-approved rollout, `NEXT_RELEASE_DEFAULT_ENABLED=true` enables the experience when a new hosted workspace is created. It does not override existing workspace choices. Existing workspaces must be enabled deliberately after migration and deployment; unset the flag to restore legacy defaults for future signups. Disabling exposure uses the current compatible Worker, not an older binary that lacks the new security and retention rules.

Apply migrations 0011–0021 before deploying the matching Worker and static interface. Back up the database and validate a migrated copy first. Roll back exposure by disabling the workspace beta; do not remove additive tables or erase conversation history.

The free-beta operating limits, required ingress bindings, resource budgets, account restrictions, and rollout controls are documented in [Operating the free beta](free-beta-operations.md). `npm run test:hardening` exercises the parser, current authorization, storage accounting, resource admissions, and HTTP/MCP permission boundaries; CI runs it alongside the legacy and beta suites. These application limits do not provide a guaranteed dollar billing cutoff. Hosted routine activation remains operator-disabled by default, independently of each workspace's beta setting.
